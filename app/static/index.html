服务端与客户端配置说明

一台电脑运行 WorkBuddy 服务端，保存微信账号并执行签到。其他电脑在 Hermes 或兼容 OpenAI Chat Completions 的客户端里填写 API 地址和网关 API Key，即可使用服务端模型。

准备服务端

可使用装有 Docker Compose 的 Linux、macOS 或 Windows 电脑。Windows 和 macOS 用 Docker Desktop 运行 Linux 容器。服务器需要保持开机并联网，休眠期间无法处理模型请求或签到。

首次部署先安装 Git、Python 3.9+ 和 Go 1.26+，然后克隆项目并构建与服务器架构对应的网关。

git clone https://github.com/richducks/WorkbuddyCCswitch.git
cd WorkbuddyCCswitch
cp .env.example .env
python3 scripts/build_gateway.py
docker compose up -d --build
docker compose ps

在 Windows PowerShell 中用 Copy-Item .env.example .env 和 python scripts/build_gateway.py。已有 .env 时直接编辑现有文件。换服务器时，停掉旧实例后私下迁移 data/gateway/ 和 data/web/，并跳过日志和 Unix 套接字；同一批微信账号只在一套实例中运行。

配置域名和路由器

  1. 选一个子域名，例如 api.example.com。在域名服务商处添加 A 记录，指向服务器或路由器的公网 IPv4。公网 IPv4 会变化时，配置路由器的 DDNS 自动更新解析。只有能从外网访问 IPv6 时才添加 AAAA 记录。
  2. 在路由器上为服务端电脑预留固定的局域网 IP，然后添加两条 TCP 端口转发。公网 80 → 服务器局域网 IP:80 和公网 443 → 服务器局域网 IP:443。公网 IP 直接分配给服务器时，在服务器防火墙或云安全组允许 TCP 80、443。
  3. 如果路由器的 WAN 地址处于运营商 CGNAT，需先取得可入站的公网 IPv4，或采用可达的 IPv6 或隧道方案。DNS 解析成功本身无法打通入站访问。

启用 HTTPS 模型入口

在服务器项目目录编辑 .env，保留本机绑定，把示例域名换成你的真实域名。域名字段只填主机名。

BIND_IP=127.0.0.1
WB_API_DOMAIN=api.example.com

启动前确认模型网关启用了 API Key。以默认网关端口请求 http://127.0.0.1:8317/v1/models，省略 Key 时应返回 401。然后启动代理，Caddy 会为域名申请并续期 HTTPS 证书。

docker compose -f docker-compose.yml -f docker-compose.https.yml up -d workbuddy-hermes workbuddy-https
docker compose -f docker-compose.yml -f docker-compose.https.yml logs --tail=80 workbuddy-https

如果 80 或 443 已被反向代理占用，复用现有代理，并只转发 GET /v1/models 和 POST /v1/chat/completions 到模型网关。

通过 SSH 使用管理网页和用量查询

先在服务器启用 SSH 密钥登录，并确保客户端能连到服务器的 SSH 端口。如果要从公网使用 SSH，单独放通或转发该端口。管理网页默认宿主机端口为 8080，下面以服务端使用 18080 为例。核对服务端的 HOST_WEB_PORT 和 HOST_BRIDGE_PORT，相应修改每个转发项最后的端口。

ssh -NT -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:18080 -L 127.0.0.1:8318:127.0.0.1:8318 SSH用户@服务器域名

保持 SSH 窗口打开。浏览器访问 http://127.0.0.1:18080/，用控制台账号密码登录。CC Switch 用量查询填写 Base URL http://127.0.0.1:8318、请求 GET /usage、提取器 response.entries，凭据使用服务端私有文件 data/web/bridge.token 中的 Token。若模型 API 也要走 SSH，在同一命令里加入 -L 127.0.0.1:8317:127.0.0.1:8317，客户端改填 http://127.0.0.1:8317/v1。

从外网验收

用手机热点或其他外网测试，避免路由器的 NAT 回环影响结果。

nslookup api.example.com
curl -i https://api.example.com/v1/models
curl -i https://api.example.com/api/summary
  • 域名解析应指向当前公网地址。模型列表省略 Key 时返回 401，用客户端填入正确 Key 后应能读取模型列表。
  • 管理路径返回 404。端口 8317、8318 和管理端口保持本机绑定。
  • 如果连接超时，检查端口转发、服务器防火墙和公网地址。证书签发失败时，检查 DNS、80/443 的入站连通性和 Caddy 日志。出现 502 时，检查 docker compose ps 中网关是否运行。
