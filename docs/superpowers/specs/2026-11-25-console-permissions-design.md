# WorkBuddy 控制台权限管理设计

## 登录与部署

用 Flask-AppBuilder 提供用户名和密码登录，以及用户、角色、权限管理页面。将现有控制台和 API 接入同一 Flask 应用，共用登录会话。现有控制台继续使用 18080 端口，账户池、签到和模型页面沿用原有页面与业务逻辑。

启用权限管理后，控制台和受保护 API 均要求登录。本机免令牌模式仅能在关闭权限管理时使用。通过部署配置显式选择模式，避免旧的免令牌配置绕过权限。模型网关和 CC Switch 用量桥继续使用各自的凭据。

## 初始化与权限

首次启动时，在本机部署中初始化 `admin` 和约定的初始密码。应用从本机部署配置读取初始密码，只在权限数据库中保存哈希。首次登录仅开放改密和退出。改密后才可进入控制台与管理后台，重启时保留新密码。局域网部署使用管理员自设的初始密码。

管理员可管理用户和角色、操作账号池、维护签到设置、查看对接密钥。普通角色按业务权限授权。默认提供只读角色，可查看账号池状态与模型目录。单独授权账号操作、自动签到设置、提供商配置和密钥读取。每条 API 按 HTTP 方法与业务动作校验权限，旧的账号转入接口与双向移动接口共用同一个权限。用户停用或取消授权后的下一个请求按新状态校验。

权限数据库和会话签名密钥存放在现有私有数据卷。账号凭据文件和签到历史沿用现有存储。启用失败时保留登录保护并返回明确的启动错误。

## 验收

- 验证管理员可以用约定的初始密码登录，改密后才能访问控制台和权限后台，重启后初始密码仍失效。
- 验证匿名请求、只读账号和缺少对应权限的账号无法移动或移除账号、修改设置或读取密钥。
- 验证管理员可以创建用户和角色、调整授权，角色撤销后旧会话也受限制。
- 使用测试账号核验双向移动和积分隔离，并验证网关、用量桥和现有控制台的入口。
